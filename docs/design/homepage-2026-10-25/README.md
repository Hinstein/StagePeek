# StagePeek 首页设计探索 · 2026-10-25

品牌决定：采用 D2 Arena Bowl（环抱场馆），紫色环形看台配荧光绿舞台。正式品牌 SVG 已更新，当前工具首页的功能与路由保持原状。

本轮回答的问题：首次访问者能否一眼看懂 StagePeek 是什么、能做什么、如何使用；哪一种首页表达最适合产品。

## 五个方案

本地启动：`PORT=4181 npm run start:local`，使用独立端口以免影响仍在运行的旧项目。

统一入口：`http://127.0.0.1:4181/mockups/home-prototype.html?variant=A`。

| 参数 | 方向 | 信息结构 |
| --- | --- | --- |
| A | 沉浸舞台 | 左侧价值主张 + 右侧大幅场馆示意 + 功能带 + 三步流程 |
| B | 快速查座 | 居中产品解释 + 可填写的票面演示 + 场馆预览 + 三步流程 |
| C | 门票故事 | 三联故事板：门票 → 定位 → 视角 + 编辑式功能说明 |
| D | 场馆探索 | 国家筛选 / 搜索示例目录 + 卡片入口 + 场馆内使用演示 |
| E | 极简视角 | 大标题 + 手机取景示意 + 三项价值 + 图文使用流程 |

底部切换栏或键盘左右方向键可切换，URL 参数可复制分享；输入框获得焦点时保留方向键的原始行为。切换栏只在本机 / 内网设计预览时显示。

初版图像均为本项目自行绘制的 SVG 概念示意，不表示某个场馆或某场演出的实测位置。B 表单仅更新示意票面文字，不进行真实坐标匹配；D 的场馆卡片进入现有真实工具，权限和数据覆盖由工具本身判断。无登录、订阅、支付或数据发布副作用。

## 设计边界

- 只在独立 `public/mockups/home-prototype.*` 下提供方案，不替换正式 `/` 的座位探索工具。
- 方案页设置 `noindex,nofollow`，不加入正式导航或 sitemap。
- 无虚构用户数、评价、演出信息或逐座准确性承诺。
- 正式选定后，整理选中的结构与文案再实现正式首页；原型与未选方案应保存到专用设计分支，不直接作为生产页面发布。

## 已执行验证

- 五个方案分别在 1280px 桌面和 390px 手机视口检查；最终均无页面或切换栏横向溢出。

- D 的国家筛选与名称搜索、E 的 1× / 2× / 5× 画面倍率、方案前后切换均已验证。
- 浏览器未记录脚本错误。静态 SVG XML、JavaScript 语法、`npm run check`、`git diff --check` 通过。
- 截图保存在本目录，属于本地设计评审资料，不是生产部署记录。

## A + E 合并方向

用户选择 A 的主布局，并要求轻量加入 E 的观众 / 手机视角。因此在 A 的功能带与三步使用说明之间加入单个紧凑模块：左侧短说明与 1× / 2× / 5× 演示，右侧缩小的手机取景示意。保留原首屏和其余结构。

浏览器已验证 1280px 桌面、390px 手机布局没有横向溢出，倍率按钮可独立放大当前模块画面；E 原稿倍率保持独立。桌面截图：`a-with-view-desktop.jpg`，手机截图：`a-with-view-mobile.jpg`。仍为原型，未替换正式首页。

## StagePeek 更名与鸟巢交互预览

正式品牌已更新为 StagePeek，域名为 https://stagepeek.live；GitHub 仓库为 Hinstein/StagePeek。已选 A + E 布局的首屏示意接入现有鸟巢目录数据与产品 Three.js 渲染器，支持旋转、缩放和靠近分区。它是未实测校准的参数化看台模型，分区标签为示意，没有当场演出舞台；不能理解为真实逐座或官方 CAD。设计页仍是独立预览，没有替换正式根路由。新品牌的预览截图在 `stagepeek/`。
