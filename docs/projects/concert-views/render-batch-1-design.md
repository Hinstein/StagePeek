# 第一批座位渲染：数据盘点与设计规格

> 历史设计（2026-10-29），不是当前派工单。当前执行以 [建模总流程](venue-shell-event-workflow.md) 和 [O2 版本快照](o2-render-method-2026-10-30.md) 为准；下文批量候选和旧待办不自动启动。后续实现已采用独立连续结构与共享显示坐标，不能再归结为接线和四个常数。

日期：2026-10-29。读者：执行方（Codex）。本文自包含，不需要前序对话。
目标：先只用 The O2 Arena 的已有逐座数据，按统一推导模板渲染出“本地研究 v0”，提供舞台、楼层、分区和相对距离的**大致参考**。

本阶段不验证用户意愿，不追求米级校准，也不把研究资产送入公开目录。参考站已经证明本产品层级的核心价值是“哪个区离哪个舞台大概多远”；四遍法验收的是这种关系是否一眼可读。

---

## 0. 结论先行

1. **数据不是瓶颈。** 仓库里已有 **50 个场馆、535,954 条逐座记录**（按默认布局去重 435,547 条），运行时可以直接加载（`server/source-seats.mjs`）。
2. **但 43 个场馆在研究层。** 只有 7 个在公开目录；其余 43 个 `researchOnly: true`，被 `loadVenues()` 默认过滤掉。
3. **原先低估了结构模型问题（此判断已撤回）。** 渲染器、逐座解码、相机模式、双主题调色板都已存在并在用；缺"参数层与座位层合并"、通道缝、座位间距常数、座位级场馆的舞台/地坪。
4. **后续候选中有 12 个欧美研究馆**，但不属于本轮；先把 O2 做成可读的参考样板。
5. **这批只能做本地原型，不能发布。** 资产元数据写着 `rights: "Public page snapshot; commercial reuse permission not established."`。反推参数也不能自动消除来源权利问题；公开发布仍需独立的权利决策与对应发布校验。

6. **本轮只做 O2。** 其他研究馆、纯参数馆和公开目录均不在本轮范围内；O2 v0 通过后先冻结，再单独决定权利和后续事件流程。

### 0.1 方法论：四遍法

参考站的制作过程是观测不到的，我们只观测到它的产物。下面这套顺序是从产物反推、并用来复现它的工作法：
它不是指标，是**顺序**——每一遍只回答一个问题，只调一个旋钮。

| 遍 | 只回答一个问题 | 只调什么 | 没过通常长这样 |
| --- | --- | --- | --- |
| 1 剪影 | 缩到 200 px 宽，还认得出是个碗吗？ | 层的划分 + `tiers` 的 a/b/depth/base（拟合值可微调） | 散块、断层、环悬浮、少一整层 |
| 2 密度 | 放大到一排，能数清有多少个座位吗？ | 椅心间距、椅宽 | 糊成连续一条线，或每把椅子像方块 |
| 3 结构 | 能找到一条从内圈通到外圈的缝吗？ | 分区端缝、区间缝 | 整圈连成实心带，一条缝都找不到 |
| 4 构图 | 一眼像不像一张场馆图？ | 相机、标签、舞台 | 场馆缩在一角、标签叠在一起、看不出有没有舞台 |

**"没过长什么样"只是帮你识别，不是让你去消除它。** 看到散块就调散块，不要顺手把别的也调了。

**规则：上一遍没过，不许进下一遍。** 四遍混着调，你永远不知道是哪一处起了作用，最后会退化成"再调调看"。

四遍法回答的是“大致参考是否清楚”，不是“几何是否已经实测校准”，也不是“用户是否会使用”。

### 0.2 只有三条硬门槛

其余全部是**信号**——用来决定下一步调哪里，不用来决定能不能继续。

| 硬门槛 | 为什么是硬的 |
| --- | --- |
| G1 来源记录数、身份和 XYZ 保持；附加显示分项计数 | 来源、参考、示意及事件椅分别核对，不再要求显示总数等于资产数 |
| G2 坐标有限、整椅受排面支撑、通道和舞台检查通过 | 使用实际支撑面；外接范围不能替代内场或分层包含检查 |
| G3 页面能打开、控制台无 WebGL 错误 | 能看 |

三个都过，就继续；任何一个不过，停下来修 bug，不要调观感。

G1–G3 只证明 v0 的数据、几何和页面没有硬错误，不把它们解释成权利或公开发布许可。

### 0.3 信号表（只指导，不阻塞）

| 信号 | 参考值 | 不达标时先动哪 |
| --- | --- | --- |
| 单椅可辨识度 | 1600 px 截图里 ≥ 3×3 px | 相机 → 椅宽 |
| 场馆占画面 | ≥ 70% | 相机 |
| 每层通道数 | ≥ 1 | 分区端缝 |
| 拟合 rms | 未校准模型单位，只记录当前配准误差 | 不能称为米，也不能单凭残差判断平顺 |

信号不达标不是你做错了，是**告诉下一刀切哪儿**。

### 0.4 反模式（这个项目之前就是这样卡住的）

| 反模式 | 后果 | 本次怎么防 |
| --- | --- | --- |
| 先建指标，再开工 | 指标互相冲突，永远不"达标" | 只留 3 条硬门槛 |
| 多个馆一起调 | 改一处，无法归因 | **先只做 O2 一个馆**，四遍走完后再单独决定扩馆 |
| 用"准确"验收"好看" | 两件事永远对不上 | 好看用四遍法，准确留到第二阶段 |
| 为过程写报告 | 报告替代了产品 | 这批只产出截图，不产出审计 |
| 一次改五个参数 | 不知道谁起作用 | 一遍只动一个旋钮 |

### 0.5 单馆节奏

不再承诺“一个馆 30 分钟”。按明确问题和验收画面收口：

```
render → 截图 → 对照四遍法找到没过的那遍 → 只改那一处 → 再截图
```

连续两次改同一处还没过的，**停下记录现象**，不要在同一个参数上反复微调。这是最容易滑回"再调调看"的地方。

### 1.5 结构性缺口

| 缺口 | 现象 | 影响 |
| --- | --- | --- |
| 层分离 | 参数层与座位层是两套记录 | 同名场馆重复（如 `kspo-dome` 有参数无座、`twcv-kspo-dome-seoul` 有座无参数） |
| 无 tiers | 43 个座位场馆 `tiers: []`、`geometry` 为空 | `venueFloor()` 回退 48×48，舞台无法定位 |
| 无 floor | 同上 | 舞台会摆到看台里面 |
| 无 stage | 资产不带舞台 | 首屏没有演出感 |
| 权利未清 | `rights: "commercial reuse permission not established"` | 只能本地预览，不能发布 |

### 1.6 两个门，不要混成一道

这一节回应"数据够不够发布"的争论。仓库里实际有两道不同的门：

| 门 | 校验函数 | 要求 | 43 馆当前状态 |
| --- | --- | --- | --- |
| **场馆进公开目录** | `server/venue-import.mjs` `validateVenueManifest` | id / name / city / capacity / HTTPS source / `tiers` 非空 / `sections` 非空且角度合法 | **只差 `tiers`**（外加 `researchOnly` 标志） |
| **事件发布** | `server/event-publication.mjs` `validateEventPublication` | 事件专属 URL、provider 双方 ID、音乐类且已复核、四段验证历史（candidate→source-matched→geometry-checked→reviewed）、`venue-metres` 布局、`seatLayoutId` 匹配 | 不适用（这批没有事件） |

结论：

1. **场馆门比事件门低得多**，而且已经写好。逐座数据、米制校准、事件布局都不在它要求里。
2. 43 个馆卡住的原因是 **`tiers` 为空 + `researchOnly`**，不是 `validateEventPublication`。
3. 所以 T2 补出 `tiers` 之后，**场馆层就具备进入公开目录的资格**（标注 `estimated` 或 `calibrated`）；
   事件层仍然走严格门，两者互不阻塞。

把这两道门混成一道，就会得出"要等事件图齐全才能上线座位视图"的结论——那正是循环重新开始的地方。
**权利问题另算**（见 1.5），它是一道独立的闸，不属于这两道门，也不由代码校验。

## 3. 本批唯一的验收动作

### 3.1 判定标准：和上一版比，不和参考站比

每一遍都摆三张图，但**只用前两张做决定**：

| 图 | 用途 |
| --- | --- |
| 上一版截图 | 判定基准 |
| 这一版截图 | 判定对象 |
| 参考站截图 | **只用来看"还差多远"，不参与判定** |

规则：这一版在**当前这一遍**上明显比上一版更能表达舞台、楼层、分区和相对距离，就过。
"明显"指一眼能看出来，不需要解释、不需要量。

**第一次没有"上一版"。所以第一件事是出一个 v0**：把座位按现有逻辑渲染出来，丑没关系，
它只承担一个功能——当后面所有对比的基准。

**v0 免的是观感验收，不是全部检查**：它必须通过 0.2 的三条硬门槛，并且满足标注要求
（舞台标"示意"、不把研究数据说成已发布）——否则解码、层级或坐标错误会被伪装成"只是还不好看"。

**禁止**把参考站截图当像素基准做叠加、比对、相似度计算。它的作用是校准你的眼睛，不是当靶子。
一旦开始"差 12% 像素"，就又回到用指标卡自己了。

### 3.2 四遍的提问方式

1. 缩到 200 px 宽：这一版比上一版更像一个能表达相对距离的场馆碗了吗？
2. 放大到一排：这一版能数清椅子了吗？
3. 找缝：这一版能看到通道了吗？
4. 一眼看：这一版像不像一张场馆图？

全答"是"，这一馆过。**不做参考图像素比对，不把米级误差写成 v0 失败条件。**
0.3 的信号表是"没过时该调哪"的提示，不是判定标准。

### 3.3 什么情况下可以判定"这馆做不出来"

只有一种：**同一处连续改两次、四个问题里有一个稳定答"否"**。
这时不要继续调，记为 `blocked`，写一句现象（例如"座位环与层高对不上，疑似层合并规则不适用"），跳下一个馆。

这是唯一允许放弃的情形。其余情况一律当作"还没调对"。

## 4. 推导规格

详细常数与配色见 `docs/operations/reference-composition-spec.md`，此处只列执行要点。

### 4.1 常数（从参考站逐座数据反推）

| 常数 | 值 | 用在哪 |
| --- | ---: | --- |
| 椅心间距 `seatPitch` | 0.50 m | 画座位 |
| 有效弧长/座 `seatSlot` | 0.58 m | 算容量（**保持不变**） |
| 椅宽 `chairWidth` | 0.46 m | 椅子尺寸 |
| 行距 `rowDepth` | 0.85 m | 排间距 |
| 升起 `riser` | 0.35 m | 层内坡度 |
| 分区端缝 | 0.60 m ×2 | 每区两端 |
| 区间缝 | 0.40 m | 相邻分区 |

关系：`0.50 / 0.58 ≈ 0.86`，即约 14% 弧长被通道吃掉。**容量模型不改，渲染模型改。**

### 4.2 层合并规则

1. 按实测 `base` 升序排层（**不要用 id 顺序**）。
2. 相邻层高差 < 1.5 m 且径向范围重叠 → 合并为一层，`steps` 相加。
3. 满足以下任一条的层判为**包厢层**，不建 tier：座位数 < 400 或 每区排数 < 6 且 层名匹配 `/box|suite|loge|club|包廂|包厢/i`。
4. 层底 `base ≈ 0` 且半径 < 内层 → 判为**内场**，不建 tier，交给演出布局。
5. 合并结果必须写进校准记录，注明每一层对应哪些来源层 id。

### 4.3 形状与 `power`

用实测的 `diagonalGain = r(45°) / ((outerX + outerZ) / 2)` 判定：

| diagonalGain | 判定 | 参数 |
| --- | --- | --- |
| < 1.10 | 圆形/椭圆碗 | `shape: "oval"`, `power: 1` |
| 1.10–1.25 | 圆角矩形 | `shape: "rounded"`, `power: 0.60` |
| > 1.25 | 矩形球场 | `shape: "rounded"`, `power: 0.48` |

### 4.4 tiers 与 floor

**不要用 x/z 两个轴向量测。** 对非圆形碗（O2、United Center 都是）轴向深度会算成 1.19 m/排，明显错。
正确做法是把每一层的边界点直接拟合到渲染器自己的曲线上：

```
r(θ) = 1 / sqrt( (sinθ / a)² + (cosθ / b)² )
```

步骤：

1. 以该层座位的外缘圆拟合中心 `(cx, cz)`（迭代 4 次，取每角度分箱最远点）。
2. 按 72 个角度分箱，取每箱的**最小半径**点 → 前缘点集；取**最大半径**点 → 后缘点集。
3. 对两个点集分别做上式的最小二乘拟合（粗网格 21×21 → 局部二分 24 轮），得到 `(a_in, b_in)` 与 `(a_out, b_out)`。
4. `depth = ((a_out - a_in) + (b_out - b_in)) / 2`。

已验证的判据：`depth / rowsPerSection` 应落在 **0.70–0.90 m**。实测 O2 0.82–0.83、United Center 0.73–0.81，成立。

| 字段 | 取值 |
| --- | --- |
| `a` | `a_in` |
| `b` | `b_in` |
| `base` | 该层最低 `y` |
| `depth` | 见上式 |
| `rise` | 该层最高 `y` − 最低 `y` |
| `steps` | `round(rowsPerSection)` |

**拟合质量只记录，不设门槛。** `rms ≤ 2.5 m` 记为 `fit: "good"`，否则记 `fit: "low"`；
端台布局的内缘不是闭合环，`rms` 3–4 m 是正常的，不改参数、不阻塞。
端台布局的内侧边界不是闭合环（舞台一侧没有座位），内缘拟合会偏，`rms` 常在 3–4 m——
这不影响外形观感，但**不能用于"校准"声明**，只能用于本批的观感验收。

`geometry.floor = [2 × 最内层 innerX, 2 × 最内层 innerZ]`。
`coordinateSystem` 必须是 `profile-inner-radius`，否则 `tiers[0]` 会被当成中径。

### 4.5 舞台

资产不含舞台。无演出时按布局规则生成一个**示意舞台**：

- 端台：中心点 `[0, 0, -(floorZ/2 - 6)]`，宽 `min(34, floorX × 0.45)`，深 16，高 12。
- 四面台：中心点 `[0, 0, 0]`，边长 `min(24, floorX × 0.3)`。
- 必须是线框或半透明，标注"示意舞台"，不得与 `estimated` 标签冲突。

### 4.6 相机与标签

| 模式 | 距离 | 仰角 | 目标 |
| --- | --- | --- | --- |
| 总览 | 1.9 × 外沿跨度 | 32° | `topHeight × 0.35` |
| 分区 | 2.5 × 分区宽 | 18° | 分区中心 |
| 观众 | 座位 + 1.2 m | — | 舞台 + 0.9 m |
| 手机 | 同观众，FOV 38° | — | — |

标签锚点 = 分区外沿中点 + 向外 1.5 m；按角度做 3 档纵向避让；任意两标签不得重叠。
