## 十馆批次与复用方法（2026-11-03）

在整合工作树 `integration/main-venue-views` 中，保留 O2、Hydro，按 Accor、Ziggo、Uber、Kia Forum、United Center、UBS、Prudential、State Farm 顺序接入八馆。逐馆场次、来源数量和预览链接以 [子项目入口](README.md#十馆批次--2026-11-03) 为准。巴黎、阿姆斯特丹使用明确标出年份的 2025 历史演出，不能冒充近期场次。

本批采用同一条接线流程：

1. 复用保留的场馆座位资产，校验数量、哈希与区排座；原 XYZ 不随显示优化改写。
2. 只为已选演出保存原图、来源、日期、配准和不可变草稿；不把站区自动解释为座席。
3. 通过 `source-bowl-display.mjs` 保留来源椅子，并由 `source-bank-shell.mjs` 独立生成平顺分区边界、连续踏面/立面、侧后封闭面、通道步面和层间平台；通过 `source-event-display.mjs` 生成事件区域、内部标签锚点、人物与示意内场椅子。2D/3D 共用同一组对象。
4. 同场内场座席共享正交方向、行列起点与间距，不逐块朝向舞台导致扇散；内场椅子完整脚印必须避开舞台、设备、区域边界与洞，保留通道；点击只产生无票号视点。来源看台保留已有区排座查询，未知号不能换成附近椅子。
5. 复用生产页面的查询表单与外层布局，场景使用 `public/venue-view/` 的工具栏、暗紫主题、手机框和相机规则；不得逐馆复制一套控件，或因资料少而删除功能。
6. 数据/几何测试通过后逐馆查看总览、2D、观众与舞台，再检查入座拖动/变焦固定眼位、2D/3D 切换、全屏、屋顶、4:3 手机框、事件退出和未知号拒绝。390px 屏幕另查表单溢出与全屏画面。
7. 将入口、代表画面、实际结果和限制追加到同一项目目录；功能接线通过只关闭功能检查；视觉停止还须完成剪影、密度、结构、构图四遍，无需以完整 CAD 或真实票务库存为前置。

**固定的结构规则：** 来源椅子与估算结构分开；短排和点云孔洞不直接产生建筑缺口。每区每层拟合连续侧边界并支撑完整椅子脚印；相邻排连接立面，侧后封闭，层间有对应下层才补平台。窄通道可补步面，但交叉/夹尖多边形及覆盖来源椅子的步面不允许生成；宽服务口与舞台开口不跨接。二维总览使用结构轮廓，放大后显示来源细节。左右不一致先查来源与同层同排，不盲目镜像真实座位。

八馆此次结构修复不改变来源身份、XYZ、共用椅子/暗紫主题/相机；模型仍是估算支撑结构，不宣称建筑 CAD。逐馆当前截图及 87/87 回归见 [八馆连续结构修复](README.md#八馆连续结构修复--2026-11-03)，修复前问题作为历史证据保留。低分辨率图的推定区名继续标注，人物仅用于比例与构图；场馆层与事件层发布门保持独立，当前未发布、权利未决、尺度未校准。

本批实测还固定了两条渲染约束：连续动画结束的最后一帧也必须提交渲染；SVG 座位点击圆必须透明、无描边，不能继承通用按钮样式遮住内场。相关回归和浏览器结果见 README 的十馆验收记录。

## 固定的八步

1. **锁定交付。** 明确本馆、本场、允许的估算、必验画面和停止条件。目标是区域、舞台方向及大致远近，不默认增加实测或票务库存目标。
2. **针对缺口取证。** 先读已有资料，再看用户指定参考与公开数据。REA 只回答具体缺口，保留来源、哈希及捕获不完整项；已有足够证据就停止采集。
3. **分开事实与示意。** 保存来源原件、编号依据、显示几何和事件差量。容量不能证明起始座号；经用户授权时可以作为带标识的编号推演先验。保留锚点，推演结果绝不冒充来源票号或真实库存。
4. **结构先行。** 用共享轮廓生成楼层、连续排面、通道和开口，再放同尺寸椅子；直线与圆弧共切点和切线。不用座位点云的孔洞直接推断建筑开口。
5. **统一 2D/3D。** 显示位置、边界、标签、拾取和观众眼位共用模型。总览显示分区，放大才显示排座。编号唯一、一号一椅、查询可反查，超出模型的输入明确不定位。
6. **接入本场差量。** 舞台、内场区域、MIX 和人物独立于场馆；两日期有明确绑定。常规场馆移除舞台/人物；站区不自动排椅。人物只用于构图比例。
7. **硬检查 → 四遍观感 → 交互矩阵。** 固定总览、转角、近区、观众与 2D 画面检查剪影、密度、结构、构图；再逐项执行下表。测试不能替代真实页面检查。
8. **冻结并交付。** 更新本文当前口径、代表截图、检查结果和限界。交给用户验收后归档；不自动扩馆、不重复建审计目录。只因可复现缺陷或用户明确新增范围重开。
