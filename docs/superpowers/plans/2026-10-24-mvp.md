# SeatPeep MVP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in this session. 用户要求直接完成；无需再次选择执行方法。

**Goal:** 实现邮件/Google 登录、免费/月订阅权限、三馆 2D/3D 和真实票号定位、可刷新演出与场次布局。

**Architecture:** Node 原生 HTTP 服务，SQLite 保存用户、一次性凭证、会话、订阅、已保存位置和事件处理记录。受保护场馆 JSON 经 API 返回，前端 ES modules 和 Three.js 共用数据模型。

**Tech Stack:** Node 24+、node:sqlite、node:test、Three.js / OrbitControls、Resend / Google OAuth / Stripe HTTP APIs。

**Spec:** `docs/superpowers/specs/2026-10-24-mvp-design.md`

## Global Constraints

- 不修改 `p7m-mvp` 或原实验原型，不发布、不实际扣费、不向外部发送测试邮件。
- 不伪造登录、支付、真实票号、舞台布局或坐标精度；服务凭据缺失必须显式反馈。
- 不在静态文件里打包受保护场馆数据；所有写操作校验同源，Cookie HttpOnly / SameSite，生产 Secure。
- 原始七项需求保持完整，外部服务或资料缺失不缩减完成标准。

## Review Focus

- 付费 API 绕过、过期订阅、取消到期和静态数据泄漏。
- 邮件链接被重放、登录 CSRF、Google 错误 state、未验证邮箱和账户绑定碰撞。
- Webhook 伪造、重放、乱序、错误 price/customer 和 checkout 回跳授予权限。
- 含字母/前导零/无障碍后缀的票号、未知座位不被映射到任意模拟格点。
- 演出抓取失败、历史活动混入未来、日期时区和无布局资料。
