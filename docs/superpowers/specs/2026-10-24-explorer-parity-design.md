# 场馆探索能力对齐设计

## 意图

把 SeatPeep 的场馆探索工作区补到参考站的核心能力水平，同时保留当前项目已经完成的来源身份、估算标记和全量几何净空校验。用户进入场馆后，应该能在 2D 中理解分区和舞台，在 3D 中总览、靠近分区、进入座位视角并使用手机取景框。

## 目标

- 2D 支持层级切换、缩放、旋转、重置、舞台/通道/分区统一表达。
- 3D 支持总览、靠近分区、观众视角、手机取景框、屋顶结构开关、全屏。
- 移动端将视角工具固定在场馆工作区附近，支持单指旋转、双指缩放和平移。
- 所有新视图继续显示来源、估算、未校准状态；不得把估算几何变成已验证数据。
- 保留现有 197 个场馆、582 个布局和 138,856 条来源座位身份与 XYZ。

## 非目标

- 本轮不重新测量场馆，不补造缺失的真实座位 XYZ。
- 本轮不抓取或复制参考站照片、私有模型或未授权资产。
- 本轮不实现完整照片社区、回忆、轨迹业务，只预留探索入口和状态接口。

## 方案

- 仅换颜色和卡片样式：改动小，但缺失能力仍然存在，放弃。
- 先补交互能力再统一样式：复用现有 Three.js、SVG 和状态模型，分层增加能力，推荐。
- 重做整个页面为参考站克隆：效果接近但影响登录、订阅、数据准确性提示，范围过大，放弃。

## 设计决定

2D 使用现有 SVG 分区数据，在 viewer 上叠加统一工具条；缩放和旋转只改变 SVG viewBox/transform，不修改座位或来源坐标。3D 使用现有 Three.js 场景，在同一相机控制器上增加 roof layer 和 phone framing overlay；屋顶结构是可视化示意，不宣称 as-built 模型。移动端工具通过 CSS 和 DOM 结构适配，不引入新 UI 框架。

所有视角状态由 `explorerState` 统一管理：`mode`、`cameraMode`、`mapTransform`、`roofVisible`、`phoneFrameVisible`。状态变化只触发渲染和 URL 可选持久化，不改变座位解析结果。

## 验收

- 2D 五个工具均可操作，层级切换后当前分区仍可定位。
- 3D 六个入口均可操作；观众视角只在已有位置时启用，估算位置继续明确显示。
- 东京花园剧场、味之素体育场、Tottenham、KSPO DOME 四类场馆完成桌面与窄屏抽查。
- 全量场景碰撞审计继续为 197 场馆、582 布局、0 相交。
- 完整测试套件通过，页面无控制台错误。
