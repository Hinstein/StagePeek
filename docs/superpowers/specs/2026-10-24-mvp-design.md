# SeatPeep 最小 MVP

依据：用户要求直接完成第一版；沿用已验证的场馆交互，不增加社交和拍照功能。本设计记录实施选择，不新增确认关卡。

## 产品与实现选择

- 独立目录 `seatpeep`，保留既有实验原型。当前工作区没有 Git 仓库，使用独立目录隔离。
- 采用 Node.js 24+ 原生 HTTP、SQLite、Web Crypto / crypto、浏览器 ES modules、MIT Three.js / OrbitControls。单进程服务及持久化 SQLite；不依赖第三方前端框架。
- 相比改造成大型全栈框架，此路径可复用当前交互且部署简单；相比纯静态页，它能真正执行身份、订阅及数据访问控制。代价是需维护小型服务端接口及其集成测试。
- 邮件通过一次性链接登录，首次验证即注册；Resend 发送适配器。Google OAuth Authorization Code + PKCE + 单次 state，服务端交换 token 并验证 Google 用户信息。凭据配置前不得假装登录成功。
- 访客可体验 Tottenham 的 2D/3D 与位置选择；注册免费用户另可保存位置；月订阅解锁其余场馆。付费判断由数据库订阅状态和当前周期共同决定，服务端拒绝越权获取场馆数据。
- Stripe Checkout subscription、Billing Portal 和签名 Webhook；价格绑定服务器配置的 monthly recurring Price。回跳页面不授予权限。通过 Stripe 当前订阅状态同步，不信任浏览器提交的支付结果。
- 月费为配置项，配置完成前不展示编造价格。外部 Google/邮件/Stripe 凭据属于上线依赖，先实现、通过本地协议契约测试，再明确记录实际接通状态。

## 场馆与准确性

- 范围：Tottenham、MetLife、SoFi。2D/3D 共用场馆数据，允许输入 Section / Row / Seat，并单独显示编号核实与几何校准状态。
- 使用目前已取得的一手来源与逐座采样事实。未知票号不得静默映射到模拟座位；未知几何不得显示为已测量。
- 将 Tottenham 全分区标识和已核实采样排座整理为服务端数据，保留来源、日期和字段状态。可用原创估算几何展示区域预览，同时明确其精度边界。
- 完整验收要求仍包括可靠的真实排座映射和场馆几何；仅增加“估算”文字不算完成该项。欠缺的原始平面/剖面继续搜集并记录阻塞项。
- 3D 沿用 OrbitControls 阻尼和机位缓动；移动端支持单指旋转、双指缩放/平移，观众视角支持环顾。限制像素比，页面不可见时不渲染，重建释放几何和材质。此次 MVP 没有拍照、照片上传和社区功能。

## 演出与布局

- 从官方活动页面采集，保存标题、日期、场馆、来源 URL、抓取时间、取消/改期状态；即将举行和历史活动分开。
- 实现可重复运行的刷新脚本和服务端缓存；抓取失败保留上次成功数据并显示更新时间，禁止用抓取失败覆盖成“没有演出”。
- 布局侧栏跟随演出，记录官方场次布局来源与校准状态。场次舞台未知时清楚显示未确认，并提供明确标识的通用预览，不自动套用其他艺人布局。

## 验收

1. 邮件 token 过期、重放、非本人会话、Google state/PKCE/已验证邮箱、退出均有测试；真实服务开通另列证据。
2. 访客、免费、有效订阅、过期和取消到期用户权限从服务端验证；付费数据不能从静态文件绕过。
3. Checkout、Portal、Webhook 签名/重放/事件乱序、用户归属、monthly price、周期到期通过集成测试；生产凭据和真实测试支付仍需独立验证。
4. 已知票号准确匹配采样记录；未知票号不冒充精确座位；2D/3D 选择一致；三馆数据覆盖及未知项有审计。
5. 当前演出来源可追溯、可刷新；失败和未确认布局的界面可用。
6. 桌面和手机尺寸实际浏览验证、无脚本错误；登录和订阅流程有页面反馈；最终按原始七项要求逐条验收，未验证的外部接通及几何精度不得标为完成。
