# 欧美票务提供商和权利边界

## Ticketmaster

当前项目的 `TicketmasterProvider` 和 `scripts/ticketmaster-sync.mjs` 读取 Discovery API 的事件和场馆元数据，并保留公开 `seatmap.staticUrl` 引用。API key 只在服务端使用。Discovery API 返回事件和公开图引用，不等于 Partner/Channel Partner 的实时库存、逐座可售状态、预订或购票权限。

## 其他提供商

AXS、See Tickets、Eventbrite 或场馆自有票务系统的接入方式和许可不同。没有已授权的 API 或明确的公开再分发许可时，只保存官方链接和来源元数据，不能抓取、代理或重新托管受限内容。新增提供商应实现独立适配器，输出与 Ticketmaster 相同的规范化事件字段。

## 图片和座位图

公开可访问不等于可以商业复制。默认策略是保存 URL、抓取时间、哈希、来源页面和使用备注；只在许可明确时保存或分发图片本体。不要把实时库存快照写成永久座位数据。座位图上的颜色、价格区和编号也可能属于供应商或演出方的受保护内容。

## 报告用语

可以说“公开座位图引用”“根据公开图人工描摹”“估算布局”。只有有明确逐座来源时才说“来源逐座坐标”。没有授权时不要说“官方 3D 模型”或“精确 CAD”。
